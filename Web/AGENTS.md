# Web — сайт SendFile over WiFi

Здесь фиксируются только Web-специфичные решения: используемый стек,
поддерживаемые браузеры, сборка и развёртывание.

## 1. Назначение

1.1. `Web` — публичный информационный сайт SendFile over WiFi, а не ещё одна
реализация приложения передачи файлов.
1.2. Сайт описывает возможности нативных приложений и предоставляет страницу
загрузки с официальными ссылками на доступные сборки для поддерживаемых
платформ.
1.3. Сайт не реализует протокол передачи `v1`, поиск устройств в локальной
сети, mDNS, TLS-соединения, выбор, приём или отправку пользовательских файлов.

## 2. Содержание и локализация

2.1. Страница загрузки должна ясно обозначать платформу, тип и статус каждой
сборки, а также вести только на её официальный источник загрузки.
2.2. Пользовательские тексты сайта локализуются для `en`, `ru`, `it`, `es`,
`pt` и `cn`. При реализации новые строки добавляются в общий каталог
`../localization/ui.json` вместе со всеми шестью переводами.
2.3. До выбора стека и хостинга не добавляются сторонние клиентские библиотеки,
аналитика, трекеры или внешние сервисы.
2.4. Статистика загрузок ведётся только на `plusap` для официальных файлов из
`/downloads/`. Браузерный трекер и передача данных третьим лицам запрещены.
Скрипт `scripts/download-report.py` сохраняет в SQLite агрегаты и HMAC-хеши
IP-адресов максимум на 90 дней; открытые IP-адреса из временного Nginx-лога
удаляются после очередной обработки. Отчёт доступен только по SSH.

## 3. Стек и развёртывание

3.1. Сайт собирается Astro как статический HTML, CSS и JavaScript; в браузер
не поставляются UI-фреймворки или сторонние клиентские библиотеки.
3.2. Производственный контейнер использует `nginx:alpine` только для раздачи
собранного каталога `dist`. Node.js и Astro применяются лишь на этапе сборки.
3.3. На сервере `plusap` сайт запускается отдельным контейнером `sendfile-web`
в существующей Docker-сети `kraabhost_default`, без опубликованных портов.
Caddy остаётся единой внешней точкой HTTP(S) и проксирует
`sendfile.plus-ap.ru` на `sendfile-web:80`.
3.4. Журнал загрузок монтируется в контейнер как `./logs:/var/log/nginx`.
Задача cron на хосте запускает `download-report.py --ingest` каждые 15 минут;
обычный отчёт вызывается командой `ssh plusap /opt/sendfile-web/scripts/download-report.py`.
