# Android

Здесь фиксируются только Android-специфичные решения. Общие продуктовые,
UI- и протокольные требования находятся в корневом `AGENTS.md` и обязательны
для Android без дублирования.

## 1. Платформенная основа

1.1. Android-версия является нативным приложением с тем же пользовательским
сценарием и составом состояний, что iOS и macOS, в пределах нативных правил
Android.

1.2. Идентификатор пакета приложения: `com.ao.sendfileoverwifi`.

1.3. Минимальная поддерживаемая версия ОС — Android 8.0 (API 26).

1.4. Реализация использует системные Android API для Wi-Fi, mDNS/NSD, TLS 1.3,
выбора файлов и передачи в другие приложения. По явному продуктовому решению
закрытый ключ постоянной TLS-идентичности сохраняется во внутреннем
`noBackupFilesDir` приложения, без Android Keystore: это обеспечивает работу
на устройствах с несовместимыми реализациями Keymaster. Пользователь не
сохраняет сертификаты и не выполняет ручную настройку.

1.5. Внешняя аналитика, телеметрия и передача пользовательских данных вне
локальной Wi-Fi передачи не добавляются.

1.6. Для TLS 1.3 и TLS exporter, требуемого для SAS протокола v1, используется
`org.conscrypt:conscrypt-android` версии `2.7.0`. Лицензия Apache-2.0 допускает
коммерческое использование. Зависимость не используется для аналитики и не
передаёт данные за пределы устройства.

1.7. Для создания самоподписанного X.509-сертификата локальной TLS-идентичности
используются `bcprov-jdk18on` и `bcpkix-jdk18on` Bouncy Castle версии `1.83`;
их permissive-лицензия допускает коммерческое использование. `androidx.core`
версии `1.15.0` (Apache-2.0) используется для `FileProvider` при системной
передаче полученных файлов. Эти зависимости не выполняют аналитику и не
передают пользовательские данные.

## 2. Разрешения и жизненный цикл

2.1. Перед поиском, отправкой или приёмом приложение проверяет требуемый для
текущей версии Android доступ к локальной сети и запрашивает только нужные
системные разрешения. Если разрешение отклонено, UI объясняет, что поиск и
приём по Wi-Fi недоступны, и позволяет повторить запрос через системные
настройки.

2.2. Приёмник запускается только явным действием «Получить» и публикует
службу, пока приложение активно. При уходе приложения в фон, блокировке
экрана или явном действии «Остановить» приём новых предложений прекращается.

2.3. Уже подтверждённая передача не зависит от экрана UI. Когда Android
требует этого для продолжения работы в фоне, она выполняется через разрешённый
системный фоновый механизм с видимым системным уведомлением; если ОС прервала
работу, данные сохраняются для докачки по общему протоколу.

2.4. Разрешение на уведомления запрашивается только на версиях Android, где
оно нужно для отображения статуса фоновой активной передачи. Отказ не должен
открывать доступ к файлам или сети и сопровождается понятным объяснением
ограничения фонового статуса.

2.5. Подтверждённая входящая или начатая исходящая передача запускает
`TransferForegroundService` типа `dataSync`. Сервис создаёт канал уведомлений
низкой важности, показывает направление и общий процент, не принимает новые
предложения и останавливается при успехе, ошибке или отмене.

## 3. Полученные файлы

3.1. Завершённые полученные файлы сохраняются в закрытом хранилище приложения,
не в общей системной папке `Downloads`. Незавершённые файлы и данные докачки
остаются во внутреннем временном хранилище протокола и очищаются в сроки,
заданные общими требованиями.

3.2. В шапке размещается кнопка «Ваши файлы». Она открывает отдельный экран
со списком завершённых файлов: имя, расширение и дата/время создания. Экран
поддерживает множественный выбор, удаление выбранных файлов, полную очистку
хранилища и видимую навигацию назад к главному экрану.

3.3. Действие «Поделиться» для выбранных файлов открывает системный Android
Sharesheet с безопасным доступом к копиям через `FileProvider` или другой
стандартный content URI. Пользователь сам выбирает, открыть, экспортировать
или передать файл в приложение «Фото» либо другое совместимое приложение.
Если список полученных файлов не пуст, но пользователь не отметил ни одного
файла, диалог списка не закрывается и показывает локализованное сообщение о
необходимости выбрать хотя бы один файл. Сообщение о пустом хранилище
показывается только при фактическом отсутствии полученных файлов.

3.4. Настройка «Сохранять дату файлов» выключена по умолчанию. Если она включена, Android применяет
переданный `modifiedAt` после финального перемещения файла. Стандартный API
Android не позволяет назначить `createdAt` для файла во внутреннем хранилище;
это поле передаётся по протоколу, но может остаться неподдержанным. MIME-тип
не записывается в файловые атрибуты. Отдельной настройки атрибутов нет; права,
`readOnly`, `hidden`, ACL и расширенные атрибуты не переносятся.

3.5. После успешного получения в блоке «ПОЛУЧЕНИЕ» доступно действие
«Посмотреть», открывающее экран «Ваши файлы».

3.6. Список «Ваши файлы» показывает в каждой строке чекбокс, миниатюру
содержимого для изображений и видео либо иконку типа для остальных файлов,
имя и дату/время. Имя отображается шрифтом на 40 % меньше прежнего размера
списка, дата/время — на 50 % меньше. Нажатие на имя открывает встроенный
предпросмотр: изображения, видео и текст показываются в приложении; для
прочих форматов доступно безопасное системное действие «Открыть с помощью».

## 4. Выбор и системная передача файлов

4.1. Внизу блока «ОТПРАВКА» находятся расположенные в один ряд действия
«Фото» и «Файлы». «Фото» открывает системный выбор изображений и видео;
«Файлы» — системный выбор одного или нескольких файлов и каталогов в рамках
возможностей Android.

4.2. Выбранные content URI должны быть доступны для повторного чтения в ходе
передачи и докачки. Если постоянный доступ к URI недоступен, приложение
создаёт временную локальную копию до расчёта SHA-256 и начала передачи. Такая
копия удаляется после завершения, отмены или истечения незавершённой передачи.

4.3. Приложение регистрируется в системном меню «Поделиться» как получатель
файлов и медиа, включая один и несколько элементов. При выборе SendFile over
WiFi из другого приложения Android открывает основное приложение и добавляет
полученные URI во временный список отправки. До завершения импорта в список
оригинальные файлы пользователя не изменяются.

4.4. Если внешний источник предоставил URI только на ограниченное время,
вложения немедленно импортируются во внутреннее временное хранилище. После
открытия главного экрана пользователь видит их в блоке «ОТПРАВКА» и сам
запускает поиск получателя.

## 5. Pro и Google Play Billing

5.1. Приём одного или нескольких файлов всегда бесплатен. Бесплатна также
отправка одного файла за одну сессию.

5.2. Только отправка двух и более файлов за одну сессию является платной
функцией Pro: разовой невозобновляемой покупкой в Google Play Billing.

5.3. После выбора двух и более файлов действие «Найти получателя» остаётся
доступным. Его нажатие открывает экран покупки: название «Send multiple
files», объяснение функции, цену из Google Play, признак разовой покупки,
кнопку приобретения и действие «Restore Purchase». До подтверждения права
поиска получателя и отправки не происходит.

5.4. В шапке размещается кнопка «Pro», открывающая тот же экран с описанием
функции, приобретением и восстановлением покупки.

5.5. Идентификатор товара Google Play задаётся при создании в Play Console и
не должен подменяться идентификатором iOS-покупки. Право на Pro проверяется
через Google Play Billing и восстанавливается для той же учётной записи после
переустановки. До создания товара debug-сборка использует изолированный
тестовый сценарий и не выдаёт постоянное право без успешной тестовой покупки.

5.6. До отдельного решения о подготовке релиза константа
`DEBUG_ALLOWS_MULTIPLE_FILE_SENDING` в `MainActivity` равна `true`: ограничение
Pro на исходящую передачу двух и более файлов временно отключено только для
отладки. Перед Google Play-сборкой значение обязательно вернуть в `false`.

## 6. Локализация и настройки

6.1. Интерфейс Android поддерживает `en`, `ru`, `it`, `es`, `pt` и `cn`,
включая состояния передачи, системные пояснения приложения, ошибки, экран
файлов и экран Pro.

6.2. Пустое значение локальной настройки означает автоматический выбор:
используется первая поддерживаемая системная локаль, а если её определить
невозможно — `en`. Пользователь может вручную выбрать язык или вернуть
значение «Системный».

6.3. Настройки отображаемого имени, темы, локали, доверенных устройств и
сохранения даты реализуют общий контракт раздела 5 корневого `AGENTS.md`.
Они сохраняются локально в закрытом хранилище приложения.

6.4. Список доверенных устройств хранит отображаемое имя вместе с
подтверждённым отпечатком публичного ключа. IP-адрес, порт и SAS-код не
являются идентификаторами доверия и не сохраняются как замена ключу.

## 7. Сборка и проверка

7.1. На текущем этапе требуется собирать только debug APK. Настройка
release-подписи, публикация в Google Play и выпускной app bundle выполняются
позднее по отдельному решению.

7.2. Результаты Gradle-сборки размещаются только внутри каталога `Android` и
не добавляются в Git.

7.3. Перед передачей сборки выполняются как минимум debug-сборка, статический
анализ и релевантные модульные тесты. Межплатформенная проверка Android↔iOS и
Android↔macOS выполняется по общему разделу 6.7 корневого `AGENTS.md`, когда
сетевой протокол Android будет реализован.

7.4. В каталоге `Android` хранится Gradle Wrapper 8.13 (`gradlew`,
`gradlew.bat` и `gradle/wrapper`). Сборки выполняются через `./gradlew`; JDK
Android Studio передаётся через `JAVA_HOME`, а путь к локальному Android SDK —
через `ANDROID_HOME` либо непубликуемый `local.properties`. Wrapper является
частью исходного проекта, а кэш Gradle, результаты сборок и `local.properties`
в Git не добавляются.
