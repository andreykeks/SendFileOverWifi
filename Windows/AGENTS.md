# Windows

Здесь фиксируются только Windows-специфичные решения: используемый стек,
системные интеграции, сборка, упаковка и особенности Windows API.

## 1. Целевые ОС и архитектуры

1.1. Приложение поддерживает Windows 10 версии 1809 и новее, а также Windows
11.
1.2. Выпускаются нативные варианты для `x64` и `ARM64`.
1.3. Поддержка 32-битной архитектуры `x86` не требуется.

## 2. Стек и продуктовые границы

2.1. Windows-версия является нативным desktop-приложением на C# с WinUI 3 и
Windows App SDK. Целевой runtime — .NET 8, минимальная версия ОС определяется
пунктом 1.1.
2.2. Реализация повторяет общий UI и сетевой сценарий macOS-версии: получение
и отправка по протоколу `v1`, mDNS/DNS-SD, IPv4, взаимный TLS 1.3,
четырёхсимвольный SAS, доверенные устройства, докачка и одиночная активная
сессия.
2.3. В Windows-версии отсутствуют встроенные покупки, Google Play Billing,
StoreKit, экран Pro и любые ограничители количества файлов, связанные с
покупкой.
2.4. В шапке отображаются логотип и название `SendFile over WiFi`; справа
располагается «Настройки». Полученные файлы по умолчанию сохраняются в
`%USERPROFILE%\\Downloads`; пользователь может изменить каталог в настройках.
После успешного приёма действие «Посмотреть» открывает этот каталог в
Проводнике Windows. Настройки содержат отдельный блок доверенных устройств с
их отображаемыми именами и удалением выбранного устройства.
2.5. Постоянная TLS-идентичность хранится в app-local PKCS#12-файле в профиле
пользователя, аналогично Android-версии; Windows Certificate Store и CNG для
неё не используются, чтобы не зависеть от политик экспорта ключей конкретной
системы. Отпечатки доверенных устройств и настройки хранятся только в
локальном профиле приложения.
2.6. При первом открытии входящего TLS-приёмника Windows может показать
стандартный запрос Защитника Windows на разрешение входящих соединений в
частной локальной сети. Приложение не запрашивает и не использует доступ к
публичным сетям.
2.7. В блоке «ОТПРАВКА» Windows показывает только действие «Выбрать файлы для
отправки». Оно открывает системный `FileOpenPicker` без ограничения типа;
отдельной кнопки «Фото» и отдельной Windows-медиатеки нет, как и в macOS.

## 3. Сборка

3.1. Проект расположен в `Windows/SendFileOverWiFi`. Выпускные варианты
собираются для `win-x64` и `win-arm64`; 32-битный runtime не создаётся.
Windows App Runtime включается в выпускную папку приложения (self-contained),
чтобы целевая система не требовала его предварительной установки.
3.2. Реальная сборка и межплатформенная проверка выполняются на Windows с
Visual Studio и workload Windows App SDK. macOS не является средой выполнения
или верификации WinUI-приложения.
3.3. На рабочем столе Windows VM поддерживается единственный ярлык `SendFile
over WiFi`. Скрипт `Windows/UpdateDesktopShortcut.ps1` переназначает его на
актуальный собранный EXE после каждой смены выходного пути сборки.
3.4. До публикации выпуск собирается скриптом `Windows/BuildRelease.ps1` с
явной семантической версией. Он создаёт self-contained ZIP-архивы `win-x64` и
`win-arm64`. Для текущего закрытого тестирования выпуск подписывается
самоподписанным сертификатом: закрытый ключ экспортируется только в
пароль-защищённый PFX, не добавляется в Git и хранится как минимум в двух
локальных защищённых местах вне Windows VM. Скрипты
`CreateDevelopmentSigningCertificate.ps1` и `SignRelease.ps1` создают и
применяют такой сертификат; `BuildRelease.ps1 -CertificateThumbprint <...>`
подписывает собственные EXE и DLL до упаковки. Самоподписанная подпись не является доверенной для
пользователей, пока они явно не доверят её сертификату; она не заменяет
публично доверенный сертификат для открытого коммерческого распространения.
Пользовательские изменения перед выпуском заносятся в `Windows/RELEASE-NOTES.md`.
3.5. Для стандартной установки используется единый установщик Inno Setup 6.3+
(на сборочной VM — 6.7.3).
Он содержит обе нативные поставки, выбирает ARM64 на ARM64 Windows и x64 на
x64 Windows, устанавливает приложение в Program Files, добавляет записи в
«Установленные приложения», пункт меню «Пуск» и ярлык на рабочий стол. Сборка
выполняется `BuildInstaller.ps1`; сам установщик и встроенный деинсталлятор
подписываются тем же сертификатом, что и приложение. Перед открытым коммерческим распространением
следует приобрести лицензию Inno Setup, как просит его правообладатель.
Исполняемый файл, установщик и деинсталлятор используют общий значок
`Windows/assets/logo.ico`, производный от общего `logo.png`.

## 4. Зависимости

4.1. Для реализации стандартного mDNS/DNS-SD используется
`Makaretu.Dns.Multicast` 0.27.0 под лицензией MIT. Библиотека не передаёт
данные во внешние сервисы и применяется только в локальной сети для
публикации и поиска `_sendfile._tcp.local.`.
4.2. Для взаимного TLS 1.3 и обязательного TLS exporter, из которого протокол
`v1` получает SAS, используется `BouncyCastle.Cryptography` 2.7.0 под
MIT-подобной лицензией Bouncy Castle. Стандартный `SslStream` не предоставляет
доступа к exporter. Библиотека применяется локально, не содержит аналитики и
не передаёт данные во внешние сервисы.
4.3. Приём файлов использует закрытую staging-область в локальном профиле
приложения, а после SHA-256-проверки переносит завершённые файлы в выбранный
каталог загрузки. Между TLS-сторонами применяется последовательный HTTP/1.1
поток протокола `v1`; размер блока данных — 4 MiB.
4.4. Незавершённый входящий набор сохраняет в staging-области JSON-состояние с
идентификатором передачи, публичным отпечатком отправителя, подтверждёнными
offsets и временем последней активности. При следующем запуске приёмника оно
восстанавливается для `GET /v1/transfers/<id>` и удаляется через 24 часа либо
по локальному или удалённому действию очистки.
4.5. После принятия offer место резервируется предвыделением staging-файлов
точного размера. Элементы, для которых в каталоге назначения уже есть файл с
совпадающим SHA-256, возвращаются в `202` со статусом `already-present` и не
занимают место в резерве и не передаются повторно.
4.6. Отправитель определяет общий исходный каталог выбранного набора и
формирует `path` каждого манифестного элемента как percent-encoded
относительный путь. Так структура каталогов сохраняется на получателе и не
подменяется плоским списком имён.
4.7. Настройка «Сохранять дату файлов» выключена по умолчанию и управляет применением переданных
`createdAt`, `modifiedAt` и `mimeType`. Отдельного переключателя атрибутов
нет: Windows `readOnly` и `hidden`, ACL, владельцы и иные флаги не передаются;
полученный файл остаётся обычным видимым файлом, доступным для записи.
